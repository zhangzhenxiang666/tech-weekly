OPENAI01
产品与 Agent分层开放09.29

DevDay：把 Agent 放进持续工作的流程

从一次对话，走向可持续执行、协作和交付的产品。

发生了什么

OpenAI 同场公布 Dots、云端 Codex、插件扩展及 Agents API 的计算机使用能力；GPT-6.1 Sol 也在这次大会发布。本期合并呈现，不把一场大会拆成多条重复头条。 [01] [02]

实践判断

对产品团队而言，值得评估的不只是模型回答，而是任务如何启动、在哪里执行、怎样交接，以及成果如何被用户审核。

接入条件、限制与注意事项

开放范围

Dots 面向符合地区条件的 Pro 与 Business Premium；部分组织套餐可由管理员开启测试。不同功能的套餐与推出节奏并不相同。 [01]

开发者看点

云端开发环境可复用；Agents API 将工具调用、多智能体、上下文压缩和计算机使用接入应用。MCP Events 在公告中仍是拟议规范，不应当作已经定稿的行业标准。 [01]

成本与边界

GPT-6.1 Sol 标准 API 输入 / 输出为每百万 token 2 / 10 美元。接近更高档模型的能力是厂商的评测判断，不是所有任务上的等价承诺。 [02]

↳先验证一个完整任务，再决定是否迁移整套工作流。
ANTHROPIC02
模型已发布09.28

Sonnet 5.5：关注每个任务的真实成本

速度与 token 使用效率，比单看模型档位更有参考价值。

发生了什么

Anthropic 发布 Claude Sonnet 5.5，面向日常编码与边界清晰的工作。厂商称比 Sonnet 5 快 30% 以上，多数工作成本最多降低约 30%；这些不是本期独立实测结果。 [03] [04]

实践判断

“做完一件事更省钱”不等于“每个 token 更便宜”。需要同时记录总 token、失败重试、工具调用和人工返工。

接入条件、限制与注意事项

接入信息

官方 API 模型 ID 为 claude-sonnet-5-5；标准输入 / 输出标价为每百万 token 2 / 10 美元。文档列出的上下文为 1M，常规最大输出为 128K，两者不能混用。 [04]

适用判断

可先用边界清晰的小修复、代码审查和文档整理做对照试验；不要依据一个通用榜单直接替换高风险流程。 [03]

迁移提醒

官方文档列出了思考与流式展示行为的变化。已有应用应回归测试输出解析、流式展示及工具调用，不能只更换模型名。 [04]

↳比单次任务验收成本，而不是只看价格表。
NVIDIA03
安全与行业平台发布09.28

Agent 安全：把控制放到模型之外

OpenShell 管运行边界，Sentry 加入独立的硬件监控。

发生了什么

NVIDIA 发布 Open Agent Safety Platform，组合 OpenShell 开源运行时与 Sentry 参考系统。前者执行策略与追踪操作；后者在 BlueField-4 DPU 上进行带外监控。 [05]

实践判断

权限、网络访问与停止开关需要由独立系统执行，而不只是写在提示词里。这对接触代码、客户数据和外部应用的 Agent 尤其重要。

接入条件、限制与注意事项

实现差别

公告中的 OpenShell 运行方案涉及 Vera CPU，并称开源软件可扩展至其他计算平台；Sentry 的独立监控依赖相应硬件。两者不是同一层能力。 [05]

不要误读

“毫秒级隔离”来自 NVIDIA 的表述，本期未验证其测试条件。平台发布不等于已证明任何 Agent 都不会越界，也不等于普通笔记本可零成本部署完整系统。 [05]

落地判断

小团队可先检查最小权限、外部访问白名单、审计记录和人工确认；这是一组设计建议，不是对现有系统安全性的保证。

↳让 Agent 能做事，也让系统能可靠地叫停。
GOOGLE04
模型受限开放09.30

Gemini 4 Argon：发布不等于人人可用

面向复杂、长程任务；目前先提供给受信任测试者。

发生了什么

Google 公布 Gemini 4 Argon，初期通过 Fairwind 计划向部分网络防御机构开放。公告将其定位于长程软件工程、专业工作与防御性网络安全任务。 [06]

实践判断

选型前先确认“能否接入”，再比较能力。受限测试模型不能直接进入下周必须上线的产品依赖清单。

接入条件、限制与注意事项

规格辨别

公告强调的是 1M token 的输出上限，而不是用这个数字说明输入上下文大小；长输出也意味着需要单独评估延迟和实际费用。 [06]

可用性

更广泛的开发者、企业和消费者开放仍在后续计划中。不能把宣布发布写成普通用户已全面获得访问。 [06]

评测边界

官网展示的能力和安全结果属于发布方的评测材料。本期不将它们与不同配置、不同测试集的成绩拼成统一排行榜。 [06]

↳进入技术观察清单，暂不预设公共可用。
MINIMAX05
开发工具含模型预览09.28 → 09.30

MiniMax Code：模型预览与订阅一起更新

M3.1-Flash-Preview 进入工具，v3.1.0 引入 M Plan。

发生了什么

官方日志显示，9 月 28 日的 v3.0.74 加入 M3.1-Flash-Preview；9 月 30 日的 v3.1.0 改进计算机使用、Mini Apps 等功能，并推出承接 Token Plan 的 M Plan。 [07]

实践判断

这次更新可以拿来验证“模型 + 工具”的完整体验，但预览模型能力、产品能力和订阅权益需要分开看。

接入条件、限制与注意事项

当期活动

日志注明：2026 年 10 月 1—7 日，订阅用户可在 MiniMax Code 内不限量使用 M3.1-Flash-Preview。本期检索日仍在活动期内。 [07]

费用限制

公告称 M Plan 的订阅价格与文本额度承接原 Token Plan；不限量是限定产品和日期的活动，不能推断为所有 API 永久免费或所有用户免费。 [07]

试用建议

在临时项目中交付一个小功能，检查修改范围、测试结果和权限申请。涉及真实业务数据前，先核对所选服务的数据处理条款。

↳可试用，但把限时权益与长期成本分开。
QWEN CODE06
开发工具正式版本09.29

Qwen Code 0.24.7：先看文件安全修复

本周的实用价值，藏在恢复机制和工作树清理细节里。

发生了什么

v0.24.7 的官方发布说明包含会话与工作区恢复改进，也列出避免旧工作树清理删除被忽略文件、未跟踪文件的修复。 [08]

实践判断

Agent 能否保住用户的本地成果，比一个新增入口更值得先检查。已在使用这类工作流的团队，应优先阅读这些修复项。

接入条件、限制与注意事项

还有哪些变化

版本加入 /commit 生成提交信息、按需加载工具、结构化记忆检索，并改进会话恢复与执行记录。部分 Managed 功能仍有开关或分阶段条件。 [08]

版本边界

本卡片针对 9 月 29 日发布的正式版 v0.24.7，不把后续 nightly 的新变化算进这个稳定版本。 [08]

升级顺序

先备份并在项目副本里检查未跟踪文件、忽略文件和恢复行为，再升级主要工作环境。新功能不应掩盖已有数据的保全要求。

↳先保护工作区，再追求自动化程度。
META07
产品与 Agent地区受限09.29

Muse 面向小企业：工具连接成为产品核心

让助手读懂商店、内容和业务资料，而不只处理一段提示词。

发生了什么

Meta 发布 Muse for Small Business，扩展连接器与技能，可对接 Shopify、Canva、Slack 等工具。公告说明 Muse 在美国与加拿大提供服务。 [09]

实践判断

做 AI 产品时，连接哪些业务资料、为哪个角色减少哪些步骤，可能比增加一个聊天入口更接近真实需求。

接入条件、限制与注意事项

权限承诺

Meta 表示，发布内容、发送信息或花费资金前需要用户批准。这是产品方的说明，不能替代对真实操作链路的审核。 [09]

接入门槛

基础服务免费，并提供更高用量的订阅；本期不沿用未从该公告核实的具体价格。地区、账号权限与各应用连接范围仍需检查。 [09]

产品试验

先选择只读的经营摘要或内容草稿，让人工完成最后发布；再决定是否开放修改店铺、财务数据等更高权限。

↳先连接有价值的上下文，再逐步开放执行权限。
GOOGLE RESEARCH08
研究研究解读09.29

Diffusion Controller：让图像生成更可控

用额外控制网络调节扩散过程，而不是只反复改提示词。

发生了什么

Google Research 在 9 月 29 日介绍 Diffusion Controller：将扩散过程建模为控制问题，并用独立控制信号进行微调。论文研究了监督与强化学习微调，以及参数更少的灰盒方案。 [10] [11]

实践判断

对设计工具和图像产品，这提示了一个方向：把约束与控制作为独立层，而非把所有要求塞进一段自然语言。

接入条件、限制与注意事项

时间范围

本周事件是研究博客解读。关联论文属于 ICML 2026，不能把博客发布日期写成论文首次发表日期。 [10] [11]

工程限制

灰盒方案仍有模型访问条件，不等于能直接套在任意闭源图像 API 外面。实际应用前应核对控制接口、训练数据及计算预算。 [11]

结果口径

效果提升来自作者实验，本期没有复现实验，也不将论文方案描述为已普遍可用的生产功能。 [10] [11]

↳值得跟踪实现，不宜把研究结论当现成功能。
AP / FTC09
安全与行业调查报道09.30 · 报道

消费者风险进入监管审查

记录已确认的调查事实，不提前推断调查结论。

发生了什么

美联社报道，FTC 发言人确认正在调查 OpenAI、Anthropic 等 AI 企业的消费者风险，但未提供更多细节。 [12]

实践判断

对交付给真实用户的 Agent，应保留授权与操作记录；调查本身不代表已认定相关企业违法。

接入条件、限制与注意事项

时间与证据

9 月 30 日是这篇报道的日期，并非本期已核实的调查启动日；本卡片不推断范围、进度或处罚结果。 [12]

实践建议

将用户批准、实际执行、异常和撤销入口做成可检查的产品流程，避免只留下“任务已完成”的一句话。

↳把授权与可追溯性做进交付过程。

给实践者的三条判断

以下是基于本期材料的编辑推论，不是厂商保证。

01

把成本单位改成“验收通过的任务”

同一组需求、同一套验收标准，比较费用、耗时与返工。不要从单个 token 价格直接推导整体效率。[02] [03]

02

产品价值在于上下文和交接

持续 Agent 与业务连接器出现在多个本周公告中。做产品时，应明确资料从哪里来、谁能访问、结果交给谁。[01] [09]

03

将恢复和叫停设计成正式功能

工作区恢复、文件保全、外部权限控制都有实际工程价值。不要只展示“任务已完成”，还要能检查过程与结果。[05] [08]

04 / HANDS-ON ROUTES

本周怎么试

三条小范围试验路线。以下为建议，
本期未实际运行模型或审计这些工具。

ROUTE 01 / 模型对照

拿一个小修复测试 Sonnet 5.5

适合已有 API 或编码 Agent 工作流的开发者；先做小样本，不直接换掉整条生产链。

怎么开始在临时项目中准备一个可复现问题和测试，使用 claude-sonnet-5-5，与现用模型对照。
记录什么验收结果、总 token、耗时、人工修改次数；固定工具和测试条件。
成本 / 风险标准 API 输入 / 输出 $2 / $10 每百万 token。先使用脱敏内容，不提供生产凭据。[04]
查看官方接入文档 ↗
ROUTE 02 / 完整交付

让 MiniMax Code 做一个小功能

适合评估“模型加开发工具”整体体验，而非只测试聊天回答的用户。

怎么开始用独立目录给出一个小页面或后端功能需求，要求列出修改文件并运行测试。
记录什么权限申请是否清楚，修改有没有越界，交付内容能否复现。
成本 / 风险官方日志列出 10 月 1—7 日订阅用户在 MiniMax Code 内的限时不限量活动；活动后需重新核算费用。[07]
查看版本与活动条件 ↗
ROUTE 03 / 升级验证

给 Qwen Code 做一次恢复测试

适合已经使用 Qwen Code、工作树或长任务的团队；未使用该工具的读者不必为此迁移。

怎么开始备份后在项目副本安装或测试 v0.24.7，检查会话恢复、文件保留及权限模式。
记录什么未跟踪和忽略文件是否完好，恢复后目录与权限是否符合预期。
成本 / 风险模型费用取决于所连接服务。不要在唯一的工作副本上验证清理行为；本期只核对发布说明，未验证修复效果。[08]
