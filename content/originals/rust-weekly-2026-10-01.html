Rust 1.99.0 正式发布

01

C ABI 可变参数函数定义进入稳定版，同时稳定了从原始指针获取布局信息的一组 API，并更新了 Box::leak 的使用指导。

FFIC 可变参数可在 Rust 中定义对应函数
MEMORY原始指针布局size / align / Layout 新 API
GUIDANCEBox::leak 指导区分永久泄漏与后续回收
编辑解读

维护 FFI 或 unsafe 抽象的项目值得优先阅读；普通 Web 服务可先做工具链兼容性验证，不必为新特性立即改写代码。

展开细节与实践建议

本次 C 可变参数稳定化针对 extern "C" 与 extern "C-unwind"。官方建议：如果泄漏的内存之后还要回收，优先使用 Box::into_non_null 等所有权转换接口，而不是先 Box::leak 再回收。这是文档指导更新，不应误读为所有 Box::leak 用法都被禁止。

实践建议

升级前，在独立验证环境运行测试与 Clippy，重点检查 FFI、内存管理和依赖兼容性；项目固定工具链时，应显式更新并验证该版本。

Web 与异步实验预览09 月 28 日 · 公告

让 Tokio 应用走进 Workers

02

Cloudflare 公布 Emscripten 目标的公开实验预览：为 wasm-bindgen 与 Rust Workers 增加 wasm32-unknown-emscripten 支持，并提供 Tokio 与 TCP 示例。

编辑解读

现有异步 Rust 代码有了值得验证的边缘部署路径；这不等于任意 Tokio 或 Axum 服务都能不加修改地运行。

展开细节与实践建议

方案将计时器、文件系统、套接字等能力映射到宿主环境。公告展示了基于 Tokio 的移植案例，并提供实验补丁和示例；这里的“原生 Rust”仍通过 Wasm/Emscripten 运行，不是部署原生操作系统二进制。

实践建议

适合小型验证项目。先核对实际依赖、系统调用、运行时模型与平台限制，不把实验补丁直接当作生产兼容性承诺。

Topcoat 0.9：从 SSR 到实时界面

03

Tokio 官方博客介绍 Topcoat 0.9：在服务端渲染的基础上，通过 WebSocket 长连接推送 UI 更新；文章也介绍了 Toasty 数据层的近期能力。

编辑解读

值得用来观察 Rust 全栈应用如何减少胶水代码，尤其是聊天、任务进度和实时后台界面。

展开细节与实践建议

Topcoat 采用服务端优先的思路，结合客户端 signal、局部重新渲染，以及 live! / emit!。0.9 的新增重点是长连接 server-push；文章中的其他能力不应全部当作这个版本新引入。

实践建议

先用一个小页面评估交互模型、部署与数据访问。现有 Axum + utoipa API 项目不必因此整体迁移；这是不同层次的架构选择。

编译器更快了，但要读对统计口径

04

编译器贡献者的双月回顾报告：在 2026-07-29 至 09-28 的 629 个基准测量项中，555 项改善、74 项回退，平均 wall-time 减少 4.57%。

编辑解读

这是工具链效率的积极信号，但并不表示本周提升了 4.57%，也不代表你的应用运行速度变快。

展开细节与实践建议

文章讨论了新借用检查器、trait solver 与其他优化。所报数字来自特定基准集合和两个月的比较区间；不同项目、构建模式和硬件的结果可能不同。

实践建议

需要评估升级收益时，用同一机器、依赖和构建模式对比自己的工程，并把冷构建、增量构建与测试编译分开记录。

Cargo 路径裁剪，向稳定版推进

05

稳定化 profile.trim-paths 的 PR 仍处于开放状态；9 月 23 日进入最终评论期，9 月 24 日有代码更新。拟提供 none、object、all 选项。

编辑解读

对构建产物中的本机路径处理、可复现构建与调试流程有意义，但不能视为路径隐私的绝对保证。

展开细节与实践建议

PR 涉及路径重映射、调试信息开启时的反向映射文件，以及供 build script 使用的映射信息。作者明确说明，这只是尽力裁剪，不保证完全消除路径信息。

实践建议

先关注最终决议及对应发布说明；不要把 FCP 当作 stable 已可用。试验时还应验证崩溃符号化与源码定位是否符合预期。

rustdoc 修复侧栏链接的平方级开销

06

rust-lang/rust 的 PR #162976 已合入主干，修复为重复侧栏链接生成唯一名称时的平方级行为，并补充了对应的压力基准。

编辑解读

对受大量重复侧栏链接影响的文档生成更有针对性；不能据此推断所有项目的 cargo doc 都大幅提速。

展开细节与实践建议

原实现为重复链接编号时反复从 1 开始寻找可用名称，导致特定页面出现高开销。此次变更修改了计数方式，相关压力测试用于覆盖常规基准未充分覆盖的情形。

实践建议

受类似问题影响的项目可跟踪包含该变更的工具链。已合并主干与已经进入当前 stable 是两回事，应以实际发布说明为准。

Deser 重新思考序列化的取舍

07

Deser 作者介绍其与 Serde 不同的设计，讨论 tagged enum、缓冲中间值和格式扩展类型等边界问题，并坦承运行时、二进制体积和生态兼容性的代价。

编辑解读

适合关注复杂配置、跨格式数据和序列化边界的开发者；它不是“Serde 已被替代”的信号。

展开细节与实践建议

作者用动态分发及堆上的 sink/emitter 等设计换取不同的表达能力。文章中的性能结果依赖格式和数据，不能泛化成全面优于 Serde；文章是作者的设计说明，不是行业迁移结论。

实践建议

现有 Serde 项目先整理真正遇到的边界用例。只有替代方案解决了具体问题，且兼容性与性能验证通过，再考虑局部试用。
