10 月 7 日

Rust 1.99 的 x86_64 C ABI `bool` 返回值可能误编译

官方 issue 显示，Rust 导出的 `extern "C"` 函数在特定代码形态下可能返回 0/1 以外的低字节值；1.98.0 正常，而 1.99.0 与当时 nightly 可复现。

实际影响

范围集中在 x86_64、跨 FFI 边界返回 `bool` 的代码，并不意味着普通 Rust 布尔逻辑全面失效。修复已经合入主干，但截至检索时 issue 重新开启以跟踪稳定分支回移。

展开建议与兼容性

审计 `pub extern "C" fn ... -> bool` 等导出接口，特别是入参参与布尔计算且生成 release 优化代码的路径。修复版 stable 尚未在本期覆盖区间发布；在无法等待 backport 的情况下，可评估临时以 `u8` 明确返回 0/1，但这会改变 ABI，必须同步调用方并做兼容性测试。

CVSS 9.1安全已修复
10 月 9 日

`bip322` 地址所有权验证可被完全绕过

0.0.6–0.0.10 的验证函数会验证攻击者 witness 中的公钥，却没有确认该公钥确实对应声称的 P2WPKH 或 P2SH-P2WPKH 地址。

实际影响

把 BIP-322 签名当作登录、授权或资产地址控制证明的系统，可能接受攻击者自签名为任意受害地址的有效证明。P2TR 验证不受影响。

展开升级建议

升级至 bip322 0.0.11；受影响版本已经从 crates.io yank。RustSec 明确称没有已知 workaround，nonce 也不能消除此绕过。

异步 / Web正式发布
10 月 6 日

hyper 1.12.0 增加 HTTP/1 头部大小上限并修正协议边界

新版本为客户端与服务端加入 max_header_size，并修复 Content-Length / Transfer-Encoding、Connection close/keep-alive 以及 HTTP/2 upgraded stream 容量预留等问题。

为什么值得关注

hyper 是 Axum、reqwest 等 Rust Web 栈的重要底层。头部上限有助于明确资源边界，而 framing 与连接语义修复则直接关系到代理链和异常对端的协议正确性。

展开升级建议

一般应用可先在预发布环境升级并回归反向代理、长连接、升级连接与大请求头场景。若直接配置低层 HTTP/1 builder，评估自定义上限是否会拒绝合法的大型 Cookie 或认证头。

hyper v1.12.0 ↗
开发工具重大版本
10 月 5 日

mold 3.0 发布首个 Rust 重写版本

官方称 3.0 面向 2.42.1 的直接替代，命令行、目标架构与除修复外的输出保持一致，链接性能与上一版相当；测试覆盖所有支持目标及 Gentoo 包构建。

实际影响

Rust 重写减少损坏输入触发越界读的风险，但不是“完全不会崩溃”：越界访问会转为受检查的 panic。自行构建从 CMake 改为 Cargo。

展开迁移要点

源代码构建要求 Rust 1.95+ 和 C 编译器；使用 cargo build --release，CMake 选项被移除，目标集合改由 Cargo features 控制。发行版维护者还需检查 MOLD_LIBDIR 与 allocator 配置。

落地案例Chrome 155 起
10 月 6 日

Chrome 采用纯 Rust 的 `jxl-rs` 解码 JPEG XL

Chrome 官方宣布从 155 起支持 JPEG XL 解码，并将网络不可信二进制的解析交给纯 Rust 解码器 `jxl-rs`。

为什么值得关注

这是 Rust 进入浏览器高风险媒体解析路径的明确生产案例：项目将 unsafe 限制在少量审查位置，并借助已稳定的 target_feature_11 做安全 SIMD。

展开边界说明

Chrome 的“未发现内存安全缺陷”来自其 fuzzing 与 AI review 结果，不等同于形式证明或永远无漏洞。Web 项目采用 JPEG XL 时仍应保留 AVIF/JPEG 回退，并按用户浏览器版本做兼容性判断。

RFC 已批准语言设计尚未稳定
10 月 5 日

`f16b`（Brain Float 16）RFC 获准合并

RFC #3983 为 Rust 提议一等的 16 位 Brain 浮点类型，重点服务 SIMD、点积和矩阵 API；类型大小与对齐均为 2，所有位模式有效。

实际影响

机器学习、图形与科学计算 API 未来可摆脱以 u16 或架构专用编码承载 bf16 的做法，但 RFC 合并只表示设计获准实施。

展开成熟度提示

不要据此在 stable 代码中假定 f16b 已可用，也不要锁定尚未交付的具体 API。后续仍需实现、nightly 试用、稳定化评审与发布。

生态项目正式发布
10 月 8 日

Bevy 0.20 推进 Solari、WESL 与场景系统

Rust 游戏引擎 Bevy 0.20 由 227 位贡献者完成 817 个合并 PR，带来 Solari 在 macOS/Metal 上运行、WESL 着色器、BSN 语法调整与新 UI 组件。

实际影响

这是破坏性升级较多的大版本：BSN 场景引用、枚举与列表语法变化，DLSS SDK 也需要更新。Solari 的 ReSTIR 现在可选且默认关闭。

展开升级建议

先遵循官方 0.19→0.20 migration guide，优先验证自定义 shader、DLSS、场景资产与系统顺序依赖。排程随机化可帮助暴露隐式顺序假设。

Bevy 0.20 官方公告 ↗
安全合辑条件升级
10 月 7–8 日

noyalib、libcrux 与 wasapi 发布安全修复

当周 RustSec 还披露：noyalib typed 反序列化未执行部分自定义预算；libcrux 的短密钥/特定输出长度可触发 panic；Windows 的 wasapi 安全函数可越界读。

实际影响

风险均取决于是否处理攻击者可控输入。noyalib 默认文档长度、深度和 alias 数限制一直有效，但调用方收紧的其他预算在 typed 路径曾不生效。

展开版本矩阵
  • noyalib < 0.0.53：升级至 0.0.53；无法升级可先反序列化为 Value。
  • libcrux-kem ≤ 0.0.9：升级至 0.0.10；短 hybrid key/seed 可 panic。
  • libcrux-hmac-drbg ≤ 0.0.1：升级至 0.0.2；输出长度为 65,536 的非零倍数时可 panic。
  • wasapi 0.20–0.24（Windows）：升级至 0.25；旧安全 API 改为 unsafe，安全替代为 parse_from_blob_bytes。
