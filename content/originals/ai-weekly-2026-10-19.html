10 月 12 日
推理部署混合 SSM论文 + 代码已有生产集成

ReplaySSM 把 SSM 状态改成“检查点 + 输入缓冲”

NVIDIA 与 Princeton Dao AI Lab 公布 ReplaySSM：缓存近期 SSM 输入而不是每步完整写回状态，以降低内存流量、简化推测解码回滚并控制量化误差累积。

为什么重要Qwen、Kimi、GLM、Nemotron 等混合模型的瓶颈开始从架构讨论落到可部署的内核优化。
对实践的影响适合大批量服务与混合 SSM‑attention 模型；小 batch 下论文明确未观察到同样收益。
论文结果与限制
论文 / 团队报告
  • 在 batch 256、指定 B300/H100 配置上，SSM 内核报告 1.46×–1.80× 加速。
  • 120B 级模型推测解码吞吐报告 1.85×–2.10×。
部署状态与不可外推项
  • 官方称已集成 TensorRT‑LLM、vLLM、SGLang、FlashInfer，并用于 GLM‑5.3‑Flash 与 Kimi‑K3。
  • 数字依赖模型、GPU、batch 与实现，不能当作通用端到端 SLA。

趋势观察与行动建议

由本周多个一手来源共同支持的编辑判断。
01 · 状态所有权

先画“记忆地图”，再做 Agent

Muse Wonder、Hy‑Memory 与 Notion 3.8 都把持久状态放到核心位置。产品团队应明确：哪些信息进短期上下文、长期记忆或系统记录；谁可写、谁可删、何时过期、能否跨 Agent 共享。

02 · 开放供应链

把“开放”拆成 6 个字段

建议模型目录至少记录 weights、source、data、license、commercial_use、support。Hy‑Memory、Nemotron 与 Run:ai 已证明一个“open”标签不足以指导生产决策。

03 · 可执行治理

把政策落到系统控制

欧盟协调标准、Notion MCP 管控、GitHub Agentic Autofix 都指向同一趋势：权限、审计、验证和撤销应由产品与平台直接执行。季度行动：为每个 Agent 建立数据范围、动作权限、验证器、人工中止与日志责任人。

资料方法与局限

  • 检索窗口：2026‑10‑12 至 2026‑10‑18；检索时间：2026‑10‑19 08:09（UTC+8）。
  • 与 2026‑10‑12 期原件交叉检查，移除了 GPT‑6、Claude Haiku 5.5、Windows MXC、Qwen‑Image‑2.1‑Turbo 等已在上一期覆盖的事件。
  • 优先使用官方公告、产品发布说明、官方仓库、模型卡、原始论文与 EUR‑Lex；媒体仅用于发现线索，未作为正文关键事实的唯一依据。
  • “正式可用 / 预览 / 申请访问 / 开放权重 / 开源 / 论文结果”分别标注。模型基准、吞吐与成本节省若来自发布方，均按厂商或论文团队自述处理。
  • 未对模型、工具或工作流执行独立实测；所有建议是基于文档的可执行起点，不是效果背书。
  • Google Argon 的直接 API 广泛可用性未从本次可检索的官方开发者定价页确认；GLM‑Legal 仅见申请访问入口；因此均保守描述。
  • 法规、许可证、价格、方案和地区可用性可能在检索后更新；生产实施与采购前应重新核对原文，并在需要时征求法律/安全专业意见。
