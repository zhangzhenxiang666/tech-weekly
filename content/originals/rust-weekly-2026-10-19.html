1. Rust 1.99.1 修补三个稳定版回归

Rust 发布团队推出 1.99.1：补齐可能被 LLVM 优化引入的 wcslen 后备实现，恢复 x86_64 FFI bool 返回值的零扩展，并为 macOS 的 rust-lld 加入定位 libLLVM.dylib 的 rpath。

为什么重要：FFI 问题属于错误代码生成，调用方可能看到非 0/1 原始值；UEFI 上使用 std 的项目也可能直接链接失败。使用 1.99.0、跨语言 ABI、UEFI 或绕过 rustup 直接调用工具链的团队优先升级。
实际影响与升级建议
  • 通过 rustup 使用稳定通道：运行 rustup update stable。
  • 固定工具链的 CI/容器需显式改到 1.99.1 并重跑 FFI、UEFI 与 macOS 链接测试。
  • 这是兼容性修补版；仍建议先在生产同构环境验证二进制与依赖构建。

2. Quinn/QUIC 集中披露多项远程拒绝服务问题

RustSec 同日发布一组 quinn-proto 公告，覆盖零长度 DATAGRAM 绕过接收缓冲上限、流重组与连接 ID 退休队列内存耗尽，以及无序读、出站 datagram 记账和 ACK_FREQUENCY 路径的 panic。

为什么重要：多项问题可由完成握手的远端触发；其中 DATAGRAM 接收默认启用。公告日期是本周，但修复版本并非本周新发：0.11.17 已修复三项内存耗尽，0.11.18 又修复三项 panic。
条件 / 风险修复线
零长度 DATAGRAM、流重组、连接 ID 队列造成内存增长>= 0.11.17
0.11.17 出站 datagram 记账；无序读空帧；启用 ACK_FREQUENCY>= 0.11.18
适用条件与操作建议
  • 用 cargo tree -i quinn-proto 检查传递依赖；为覆盖全部本组公告，至少解析到 0.11.18，处于 0.11.x 的项目可优先采用更新的 0.11.19。
  • send_datagram_wait 不受出站记账问题影响；ACK_FREQUENCY 默认关闭；默认有序读取不受无序读 panic 影响。
  • 升级后做 QUIC 互通、拥塞和 datagram 压测；补丁跨越内部协议状态机，不能只看编译通过。

3. Wasmtime 三条维护线同步发布安全补丁

Wasmtime 49.0.3、48.0.6 与 36.0.18 在 10 月 14 日发布。49.0.3 的修复清单包含组件模型异步调用/句柄边界导致的宿主 panic 或资源问题、递归类型栈溢出、带尾随斜杠的符号链接重命名沙箱逃逸，以及 wasi-http 主机与 URL 处理问题。

实际影响：若服务运行外部或多租户 Wasm 组件，宿主可用性和 WASI 沙箱边界需要优先评估；不要只升级 CLI，要检查应用直接依赖的 wasmtime/wasmtime-wasi 分支。
升级注意
  • 按现有维护线升级到 49.0.3、48.0.6 或 36.0.18；不同维护线回补集合不完全相同，请对照本项目所用 API 与功能。
  • 重点回归组件异步取消、WASI 文件系统重命名、wasi-http 出站请求及资源限额。
  • 这是已发布补丁，不是 50.0.0-rc.1 预发布版本。

4. mykey 的预共享密钥模式会明文暴露 SRTP 主密钥材料

mykey 在 PSK-Init 中以 NULL 加密传输 TGK，使能读取 MIKEY 消息的旁观者恢复 SRTP 主密钥并伪造消息 MAC。RustSec 将其评为 CVSS 9.1，修复于 2.0.0。

兼容性风险：2.0.0 改变线格式，两端必须同步升级；新旧端可能表面完成交换却得到不同 SRTP 密钥，属于静默不兼容。
缓解与升级条件
  • 使用 PSK 模式的 AES67、SMPTE ST 2110 或其他 SRTP 部署应立即盘点。
  • 不能同步升级时，改用临时 Diffie–Hellman 模式，或只在已有端到端机密性与认证的信道中传递 PSK-Init。
  • 升级必须安排双端切换与媒体互通验证，不适合单边滚动。

5. Tokio 1.53.3 / 1.51.6 同步修复运行时与同步原语

Tokio 同时更新两条维护线，新增 AsyncFd::register*，并弃用若干直接构造方法；修复 current-thread 运行时在 I/O 唤醒时的暂停时间自动推进，以及 DuplexStream、Semaphore 等在锁内唤醒/释放 waker 的问题。

实际影响：依赖暂停时间做确定性测试的服务、使用 AsyncFd 集成自定义文件描述符的库，以及高并发同步路径最值得回归。弃用不是立即破坏，但会影响后续无警告构建。
升级建议
  • 1.53.x 用户升至 1.53.3；固定在 1.51.x 的项目可升至 1.51.6。
  • 逐步改用新的注册 API，避免新弃用警告进入严格 CI。
  • 若测试使用 time::pause / advance，升级后重跑涉及 I/O 唤醒的用例。

6. ic-cipher 的 Poly1305 在攻击者可控长消息上可 panic 或算错标签

ic-cipher 0.2.5–0.2.19 的四块并行累加在 32 位进位上可能溢出。开启溢出检查时会 panic；默认 release 配置下则可能产生错误认证标签。影响 Poly1305、ChaCha20Poly1305 及其在 ic-rustls、ic-hpke 等上层的使用。

实际影响：攻击者无需密钥，只需让系统尝试打开至少 64 字节的特制 ChaCha20-Poly1305 密文即可触发相关路径。AES-GCM/AES-GCM-SIV 与短于 64 字节的消息不受此项影响。
升级建议
  • 将 ic-cipher 升到 >= 0.2.20；< 0.2.5 不受此问题影响。
  • 检查传递依赖中的 ic-rustls、ic-hpke、ic-mac 与 ironcrypto 重导出。
  • 不要把关闭 overflow checks 当作缓解：那会从崩溃转为错误标签。

7. Rust 基础设施强化 crates.io / docs.rs 防护与供应链监测

Rust 基础设施团队披露 Q3 进展：为 crates.io 与 docs.rs 启用 Fastly WAF 和 DDoS 防护；为 Rust 与 Rust Foundation 的 GitHub Enterprise、AWS 等接入审计日志；在 rust-lang 组织启用 Dependabot 告警，并为 rust-lang/rust 配置 Renovate 辅助依赖更新。

为什么值得关注：这些改动直接覆盖 Rust 分发、文档与项目依赖维护的公共基础面。官方明确说明未开启 Dependabot 自动安全 PR，而是偏好通过 Renovate 控制修复节奏。
更多可核实进展
  • CDN 处理 crate 下载请求的计算时间降低 10%；官方同时说明网络仍主导最终下载延迟，不能解读为用户下载提速 10%。
  • riscv64gc-unknown-linux-musl 升为带 host tools 的 Tier 2。
  • Q4 计划包括集中式安全部署环境、SAML SSO 与更严格的 crater 网络访问规则；这些仍是计划，未标为已完成。

8. Creusot 0.14.0 改善证明表达与 rust-analyzer 导航

Rust 形式化验证工具 Creusot 发布 0.14.0。新版可为嵌入 Rust 程序的 snapshot 逻辑表达式生成验证条件，使逻辑函数更自然地充当 lemma；同时让 Pearlite 规约中的“转到定义”可在 rust-analyzer 中工作。

实际影响：使用 Creusot 的团队可以更早发现规约错误，并减少为了证明而引入的运行时代码与借用检查绕行；IDE 导航也降低维护规约的摩擦。
范围说明
  • 0.14.0 是项目正式发布，不是 Rust 官方语言特性。
  • 部分偏序支持从 0.13.0 已开始，本次文章补充介绍；不应全部算作 0.14.0 新增。
  • 升级前按项目兼容矩阵检查其所需 Rust 工具链与验证后端。
